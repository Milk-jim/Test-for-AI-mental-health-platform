## 🎯 核心能力

### 1. 分层架构设计
- 自研 **五层分离架构（API / Page / Business / Case / Data）**，实现关注点分离
- 前端 UI 改版时仅维护 Page 层元素定位，**用例层零改动**
- 新业务模块接入仅需补充 Page Object 与用例，**底层设施零改动**
- **维护成本降低约 40%**

### 2. 执行效率优化
- **接口层**：利用 pytest Fixture 实现 `session` 级 Token 复用 + `function` 级独立 ApiClient 隔离，全链路仅登录一次，**接口用例耗时缩短 60%**
- **UI 层**：通过 API 获取登录态直接注入 `localStorage`，跳过 Selenium 模拟登录步骤，**UI 业务用例执行速度提升 30~50 倍**
- 保留 3 个专项 UI 登录用例独立验证登录交互本身，**分层策略兼顾效率与覆盖完整性**

### 3. 问题定位提效
- 实现 `pytest_runtest_makereport` 钩子，UI 失败时**零侵入自动截图**并采集当前 URL，写入 Allure 报告
- 缺陷复现时间从 **天级压缩至分钟级**
- 开发人员可直接根据报告独立定位问题，**减少测试与开发间的沟通成本**

### 4. 精准分层执行
- 通过 `@pytest.mark` 标记 **smoke / api / ui / 各业务模块**
- 支持组合筛选（如 `-m "api and not smoke"`），灵活支撑冒烟回归、全量回归、模块专项等不同测试场景

### 5. Element-Plus 组件库适配
- 针对 Element-Plus 定制专用定位方法：通过 `placeholder` 定位 `el-input`、通过文本定位 `el-button`、读取 `el-message` 提示样式
- 解决复杂 UI 组件在自动化中的稳定定位难题

### 6. 接口覆盖范围
- 覆盖 **7 大业务模块，30+ 核心用例**
- 用户模块 **15+ 异常场景**（重复注册、参数缺失、密码错误等）
- 知识科普全流程闭环（新增→查询→状态切换→更新→删除）
- 情绪记录边界值参数化（-1 / 0 / 5 / 10 / 11）
- AI 咨询流式响应 + 超时重试校验
- 用户端/管理端数据可见性隔离校验
